## Architectural review

The shared catalog, schemas and data models provide a useful behavioral boundary; Jekyll/Astro enhancement and React state remain distinct implementations. Source-informed Martlet and Krigsvold identities should continue to be reviewed independently. Public React Field, Dialog, ErrorSummary, Pagination and Tabs contracts were corrected in the stack and exercised through packed consumers. Field's previously undocumented derived description IDs changed; explicit `hintId`/`errorId` migration and distinct React identifier prefixes for independent roots are documented. These packages remain experimental.

No additional release-blocking defect was demonstrated in the independent review's inspected scope. A reproducible **nonblocking portability defect** remains: a Chromium test showed a host-state object becoming `null` after a Martlet Jekyll analytics filter/retry. Source inspection found `history.replaceState(null, ...)` in the other dashboard implementations as well, but those were not independently reproduced. This can interfere with an embedding router; preserve host state and test initialization and subsequent updates across frameworks in a follow-up. It does not establish loss of dashboard records. Static React articles have also been measured at roughly 74.4 KB compressed JavaScript; assess selective hydration against real use before broad refactoring. See [architecture](nightjar-architecture.md), [interaction contracts](../../examples/page-archetypes/INTERACTION-CONTRACTS.md) and [conformance review](nightjar-conformance-review.md).

## Security and compatibility decisions

The 65 GitHub default-branch Dependabot alerts (4 critical, 25 high, 24 moderate, 12 low) are not enumerated by the available connector; enforced network policy blocks direct `api.github.com`. A security manager with alert-read permission should review the [Dependabot page](https://github.com/k3jph/design-workbench/security/dependabot), or from an authorized network run `gh api --paginate 'repos/k3jph/design-workbench/dependabot/alerts?state=open&per_page=100'`. Do not share credentials. Record alert number, GHSA, severity, manifest path, affected version, dependency scope, state, fix and build/runtime reachability; reconcile all pages against the candidate, main and historical fixtures, prioritizing critical then high. Do not dismiss alerts based on clean npm audit results alone.

Separate source-site drafts [Martlet #32](https://github.com/martlettheme/martlettheme/pull/32) and [Krigsvold #31](https://github.com/krigsvoldtheme/krigsvoldtheme/pull/31) update Astro 5 to 7.3.3 and require Node 22.19 or later; local Node 22.19 builds and hosted checks passed, but CI's floating Node 22 is not proof of every deployment platform. A hosting administrator must verify Cloudflare build Node version/command, branch-preview and production triggers, Worker routes/assets and compatibility date before any deployment. The sites have `run_worker_first` Workers as well as static assets. Their checked-in prebundled Workers are outside the npm lock audits. An independent clean rebuild at source commit `39d664082bb0dbdb09bc182a6abffebef75518ff` matched the tracked Worker bytes after normalizing only source-commit metadata and reference URL; that source lock pins Zod 4.3.6, affected by high GHSA-mrhx-c7xc-m3w5. Runtime exploitability is unproven: the endpoint limits bodies to 32,768 bytes and custom schemas use bounded strings/numbers; SDK-level input paths still need review. Each site also tracks a downloadable agent archive pinning Zod 4.3.6. Its build fetches a checksum-pinned published reference archive and replaces `site/public/agents`, so modifying local copies alone is not durable. Patched regeneration and a reviewed artifact publication/repointing strategy are a priority security gate; publishing that artifact is not authorized here. No production compromise is established. See [security triage](nightjar-security-triage.md) and the current PR descriptions.

## Publication control and integration sequence

1. Review #18 and #19 as historical layers and #20 as the complete candidate; do not merge #18 alone. Obtain human review of the large framework, package API, security and application changes and resolve any newly discovered blockers.
2. Keep the candidate on its non-main draft branch. `ci.yml` calls the reference release workflow on a verified push to main. It creates a commit-qualified tag and publishes a GitHub prerelease with archives, then may create and automatically merge host adoption PRs and wait for Cloudflare production deployments. Publication happens before adoption credentials and protection checks. A separate `react-v` published-prerelease workflow npm-publishes React packages; the manual preparation workflow can also publish references when explicitly enabled. Do not rely on cancellation races, skip-CI markers, absent secrets or downstream failures to prevent publication.
3. A possible future **separately authorized** safeguard is a fail-closed protected GitHub environment on the reference workflow's publish job, with required human approval and bypass disabled; adoption depends on publish. This is a proposal, not an implemented or validated control. Merely naming an environment can auto-create an unprotected one: an administrator must pre-create and configure it, verify platform/plan support, branch restrictions, reviewers, bypass behavior and in-flight older ungated runs, and test a nonpublishing protected dry run before any main push. Changing production workflows or environment settings requires separate authorization. Alternatively, separately authorize the actual publication, adoption and potential deployments; absent either path, no safe main integration has been demonstrated.
4. Once an approved control is in place or all external actions are explicitly authorized, recheck main SHA, rulesets, reviews, required checks, hosting and in-flight runs. Integrate the complete candidate in a **single main update**, compare the resulting tree to the approved candidate and rerun required checks. Decide separately how to close or retarget #18/#19 and whether to release any package; a merge, release, deployment, workflow change, or production configuration change is not authorized by this report.

Priority backlog: (1) establish and approve publication control; (2) enumerate and assess Dependabot alerts and Worker bundles; (3) manual contrast/assistive-technology and representative visual review; (4) dashboard host history-state preservation; (5) Node/platform compatibility for source-site upgrades; (6) evaluate measured React hydration cost and continue the separately planned Jekyll extraction. The [extraction plan](nightjar-jekyll-extraction-plan.md) is planning only; no repositories were created.
