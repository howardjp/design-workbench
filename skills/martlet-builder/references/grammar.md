# Martlet: a grammar of related things

Experimental grammar 0.2 · Core 2.2.0 candidate · Astro 1.2.0 candidate · React 0.1.0

Martlet makes substantial work approachable through proportion, proximity, readable sequence, and continuity. Its warmth must survive a compact collection, an error, or a page without its mark. The adopted charter supplies the criteria; these rules turn them into an application vocabulary to exercise and revise.

## Source authority and current decisions

Existing origin objects are the baseline. Read the `decisions` MCP reference or the adjacent decisions.md before choosing visual rules. Distinguish observed source roles, a contextual translation, and a new application extension. Do not add a global gold stripe, decorative monospace labels, arbitrary accent rules, or mechanically opposite family layouts. Keep new capabilities only with a stated task purpose. The October 23 audit is a fixed record; the reconciliation ledger records implemented decisions and remaining gaps. This remains an experimental grammar, not a declaration of stability.

## Begin with relationships

Decide what belongs together before drawing containers. A label, control, and useful explanation form a field. Related fields form a group. Groups participating in one decision form a task region. Use progressively stronger separation to express those changes of relationship. Do not give every paragraph or field its own card.

The optional source profile exposes `--martlet-field-gap` at 0.5rem, `--martlet-group-gap` at 1.5rem, and `--martlet-region-gap` at 2.5rem. They map to existing foundation scale steps 2, 4, and 5. These are experimental application defaults, not a requirement to space every adjacent element equally. Use the field role inside a relationship, the group role between related units, and the region role between different purposes. A compact composition may reduce local padding while retaining the relationship hierarchy.

## Give the work a readable sequence

Establish orientation, the subject, supporting context, and the next useful action. Use a bounded reading measure for sustained text. Interface labels and metadata use Lato; Cambo supports prose and expressive headings; Cinzel remains selective rather than spreading to every control. In light mode use the observed source ink, navy heading and cream support roles; keep the actual rendered source link color. Existing dark semantic tokens supply an explicit extension with the same source anatomy. Retain original marks when identifying the system; adopting applications provide their own identity.

Reading hierarchy also applies to forms, tables, and working panels. A toolbar can be compact and a table can contain many rows. Neither requires display-size headings or article-sized spacing inside every control. Preserve an understandable sequence and proximity within each local group.

## Place assistance at the decision

Keep a field's requirement and useful hint beside it. Use explicit action labels that describe the outcome. Place an object's actions with the object, and collection actions with the collection. Do not use a row's whole surface as an ambiguous combination of selection, opening, and editing. Decide and communicate what activation does.

Reveal secondary options when relevant without hiding prerequisites. Put essential consequences in view before commitment. Warm language must still distinguish cancel, reset, discard, remove, and delete precisely.

## Preserve continuity

Use expansion and loading to explain the change, preserving useful content and the person's place. Do not erase an editor when a save fails. Announce meaningful completion and provide an immediate recovery path. On a failed form submission, show actionable errors, retain input, and move focus to a useful summary when errors are distributed.

Unsaved navigation requires a clear choice that keeps the draft available. Cancelling that choice returns to editing. A reversible removal can use an explicit undo path instead of interrupting every action with a modal. An irreversible action requires proportionate consequence guidance. Motion is optional explanation; the result must remain clear with reduced motion.

## Choose the frame from the task

Top navigation, side navigation, and focused work without primary navigation are all native possibilities. Use a rail when persistent destinations are valuable. Use a top bar when compact orientation leaves the work more room. Use a focused frame when the task benefits from sustained attention. None defines Martlet by itself.

Change the composition when available space no longer supports its relationships. Use the left source document index, with unnumbered parent/child hierarchy and separate supporting material. The inline article TOC is a different named variant. Reflow the index into a cream in-flow block when the available width is insufficient, without losing hierarchy or navigation. Preserve source order, keyboard access, readable controls, and return paths. Long labels and enlarged text are design inputs, not exceptional content to clip away.

## Working pattern: collection, reading, and editing

The Commonplace specimen lets a person browse related notes, narrow the collection, open one for sustained reading, and edit it. Its folder shelf and collection-level search provide orientation. The collection uses generous separation between ideas, with each note's heading, excerpt, and explicit reading action forming one group. Opening a note changes to a bounded reading context; a named back action returns to the same folder and query. Edit enters an explicit form; the reading context is restored after saving or cancelling.

This is one Martlet pattern, not a universal application template. A comparison-heavy task can use a persistent split view. Select it when the work requires simultaneous reference, then apply the same grouping, hierarchy, and continuity rules.

## Pattern rules and state coverage

Search stays scoped to the named folder. A no-match state explains how to recover and offers Clear search. Empty content explains what belongs there and offers creation. Choosing a different folder is a context change, distinct from changing the query. Successful saving commits the draft and announces success; failed saving retains the fields and offers retry. Leaving a changed editor asks whether to continue editing or discard. Moving a saved note to trash offers undo.

The specimen uses fictional, session-only data. Reloading restores its initial notes. The failure inspection control deliberately fails the next save; it is documentation tooling, not a production product feature. Network retrieval, durable persistence, collaboration, and rich text are outside this specimen's implementation.

## Review the grammar

Inspect relationships before decoration: can someone tell which help belongs to which control, which action affects which object, and where one task becomes another? Does the same reasoning work in a compact panel and a long form? Can they recover their place after a change? Remove the mark and reduce color distinctions; hierarchy, proportion, grouping, and interaction continuity must still carry the language.

Keyboard conventions, focus visibility, labels, and usable recovery are shared obligations with other sound systems. Do not invent unusual behavior merely to look independent. Manual assistive-technology review, localization, RTL adaptation, and sustained use remain required before stability.
